# AI через воркер

Ключі Groq і Gemini лежать у секретах Cloudflare Worker (той самий воркер, що й пошта), а не в базі.
Браузер питає воркер, воркер перевіряє, чи можна, і лише тоді звертається до провайдера.

## Що перевіряє воркер
- хто питає: викладач чи адмін (Firebase ID-токен) або студент зі сторінки тесту (лише `comments` і `textcheck`, з чинним посиланням на тест; AI рахується викладачу, запити обмежено за IP);
- дозвіл **«AI-функції»** викладача (особисто → ролі → для всіх) і режим «лише перегляд»;
- що функцію ввімкнено в адмінці (AI налаштування) і в налаштуваннях викладача;
- місячний ліміт викладача (особистий, ролі, для всіх; 0 = без обмежень), адміністратора не обмежено;
- облік використання (`aiUsage`) пише воркер.

## Налаштування (власник, один раз)
1. Cloudflare → Workers → ваш воркер пошти → **Edit code**: вставити `worker/dist/worker.js` (після змін у `worker/src` перезібрати: `cd tests && npm run worker:bundle`).
2. **Settings → Variables and Secrets → Secrets**: додати `GROQ_API_KEY` та/або `GEMINI_API_KEY`.
3. (за потреби) `AI_ALLOWED_ORIGINS` — за замовчуванням `https://app.quizflow.space,https://admin.quizflow.space,https://test.quizflow.space`; `AI_ANON_PER_HOUR` — запитів студентів з одного IP на годину (120).
4. Адмінка → **AI налаштування**: переконатися, що стоїть «Ключі у воркері», і натиснути «Перейти на воркер». Після цього «Видалити ключі з бази».

Поки в налаштуваннях AI не ввімкнено перехід, усе працює як раніше (браузер звертається до провайдера з ключем із бази).
Воркер теж має запасний варіант: якщо секрету немає, він бере старий ключ із `settings/ai`.

## Перевірка
`GET /ai/status` (адмін) показує, які ключі є у воркері, і чи лишились старі ключі в базі. Самих ключів воркер не віддає.
