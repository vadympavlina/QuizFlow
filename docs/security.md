# Безпека бази даних QuizFlow

У репозиторії лежить файл `database.rules.json` з правилами доступу до Firebase
Realtime Database. Їх перевірено 101 автотестом у емуляторі Firebase: сторінки сайту
працюють, а сторонні не можуть читати чи псувати чужі дані.

## Що закривають правила

| Було (відкрита база) | Стало |
|---|---|
| Будь-хто міг зареєструватись і сам поставити собі `role: "admin"` | Реєстрація лише з дійсним запрошенням і лише як `teacher`; змінити роль чи розблокуватись сам викладач не може |
| Будь-хто міг прочитати чи видалити всі тести, спроби, студентів усіх викладачів | Викладач бачить і змінює тільки свої дані, адмін — усі |
| Студент зі сторінки тесту міг вивантажити всі спроби й картки студентів | Студент читає лише один тест, одне посилання і шукає свою спробу/картку за ім'ям |
| Можна було переписати оцінки в старих спробах | Спробу можна змінювати лише протягом доби після створення і не можна видалити |
| Токен Telegram-бота й налаштування читались без входу | Лише для викладачів / адмінів |
| У живій грі можна було накрутити собі бали чи змінити статус гри | Гравець може лише приєднатися й один раз відповісти на питання; решта — тільки у викладача-ведучого |

## Як увімкнути (≈10 хвилин)

**1. Спочатку злийте PR з кодом** і дочекайтесь, поки GitHub Pages оновить сайт
(вкладка *Actions* → «Deploy QuizFlow» зелене). Нові правила розраховані на новий код
сторінки тесту й реєстрації.

**2. Замініть ключ Groq.** Старий ключ був прописаний у коді й лежить в історії
репозиторію, тож вважайте його скомпрометованим:
1. <https://console.groq.com/keys> → видаліть старий ключ (`gsk_vhlO…`), створіть новий.
2. Адмінка → **AI** → вставте новий ключ Groq → Зберегти.

**3. Збережіть копію поточних правил.** Firebase Console → **Realtime Database** →
вкладка **Rules** → скопіюйте все в текстовий файл (щоб за потреби швидко повернути).

**4. Вставте нові правила.** Там же замініть усе вмістом файлу `database.rules.json`
з репозиторію → **Publish**.

**5. Перевірте сайт:** вхід викладача, список тестів, конструктор, проходження тесту
за посиланням у вікні інкогніто, жива гра з телефона, адмінка. Якщо щось не працює —
вставте збережену копію правил (крок 3) і напишіть, що саме зламалось.

> Можна спершу перевірити правила в **Rules Playground** (кнопка на вкладці Rules):
> наприклад, запит `get /teachers/<uid>/attempts` без авторизації має бути **Denied**,
> а `get /teachers/<uid>/tests/<testId>` — **Allowed**.

## Що ще лишається відкритим

Ці речі правилами бази не закрити — потрібен невеликий сервер
(безкоштовний Cloudflare Worker, той самий, що й для розсилок):

- **Ключі AI (`settings/ai`) читаються без входу**, бо сторінка тесту студента сама
  звертається до AI (коментар до результату, перевірка текстових відповідей).
  Сервер тримав би ключі в себе.
- **Правильні відповіді видно в даних тесту**: тест перевіряється в браузері студента,
  тож технічно підкований студент може їх знайти. Те саме для живих ігор.
- **Токен Telegram-бота читають викладачі** (для пересилання звітів про помилки).
- **Список викладачів (імена, email) бачать усі викладачі** — потрібен для
  «Поділитися тестом» і живих ігор.

## Перевірка правил локально

```bash
npm i -D firebase-tools @firebase/rules-unit-testing firebase
npx firebase emulators:exec --only database --project demo-quizflow "node tests/rules.test.mjs"
```
